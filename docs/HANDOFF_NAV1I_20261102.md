# F407 底盘 nav1i 与机械臂 R9D 交接

更新：2026-11-02。底盘 `v2.5.0-nav1i-20261102`；机械臂 `GC1_ARM_F407VE_USART1_20261028_R9D`。这是两套独立固件，尚未合并。不要把下载其中一套误认为两套都在运行。

## 1. 当前完成情况与验收边界

用户反馈此前 nav1h/base 实车效果可以。本次硬件断开，未连接串口、DAP 或摄像头，未烧录、未动车。本版的验证级别是源码检查、生产 C 原生集成回归、ARM 交叉编译；不是本版实车验证。

本版实现了板内连续中央路线：只有作业站和终点停稳，过路点不断开控制器、不重复使能、不重新建立原点。短接近/转向段预算150RPM，较长直线预算200RPM；航向轨迹上限1.0rad/s，原同步转向约0.2rad/s。两者都受统一四轮分配限制，不保证平移速度与转速分别同时达到各自最大值。

完整生产 C＋异步串口＋10Hz IMU＋一阶驱动响应的离线检查，典型整圈约65～71秒，包含8次到站判稳及启动/最终停稳；参考轨迹自身约55秒左右。这个差别不能省略。没有证明实车能在60秒内完成，也没有证明实车厘米级精度，更没有把5秒扫码、取放物料等待包含进去。

响应0.08/0.12/0.16/0.20秒的若干离线变体能够完成；0.24秒更慢响应和较大通信延迟组合仍可能触发跟踪/轮一致性保护。把保护触发记作“安全拒绝”，不能算完成路线。装机械臂、换轮、换地面后须重新验证，不可把本版当作全载荷免整定控制器。

远端本次只发布最新STM32源码、必要库/构建入口、当前固件及本文等使用说明。没有发布MATLAB/Python仿真工程、仿真数据、串口日志、实车实测数据或本地中间版本提交。

## 2. 工程入口及构建

根目录 `src/nav_main.c` 是底盘入口。`scripts/build_nav.py` 是权威离线构建入口：GNU Arm GCC 13.3，C11/O2，Cortex-M4F硬浮点，HSE25MHz，SYSCLK168MHz。不会接触硬件。可用 `CHASSIS_GCC` 指定编译器绝对路径。

```powershell
python scripts/build_nav.py
```

输出 `build/nav1i/chassis-nav1i.bin/.hex/.elf`，以及构建来源/摘要 `build.json`。发布产物位于 `firmware/current/`。`chassis.cproject.yml` 已改成相同的当前nav源码和 `STM32F407VE_nav.ld`；CMSIS工程本轮未用CMSIS-Toolbox单独构建，验证过的是Python构建入口。

机械臂：`powershell -ExecutionPolicy Bypass -File arm/build.ps1`。Keil ARMCC5.06，工程 `arm/project/MDK-ARM/GC1_Arm_F407_R9D.uvprojx`，目标 `ArmBenchF407`。脚本先从 `arm/platform` 同步BSP/头文件，再构建。当前机械臂仅重新编译，0错误0警告；其动作成功的依据是此前用户实车反馈，不是本次重测。

旧底盘entrypoint、旧HEX和研究工程不在本次发布快照内。不要使用旧工具默认指向的vel1/nav1c二进制烧录本版。

BOOT0低。F407VET6为512KiB Flash、128KiB连续SRAM；本版不使用CCM。主控按开发板规格供电；舵机/电机动力电源及大电流回路不经过DAP或主控细地线。不并接两个供电输出。

四轮顺序FL、FR、RL、RR，地址分别4、1、3、2；编码器原始符号分别+、−、+、−。前进 `++++`，后退 `----`，左移 `-++-`，右移 `+--+`，逆时针 `-+-+`。驱动器UART_FUN、115200、校验0x6B。串口地址和机械安装变更后先重新核对方向。

## 4. 坐标、路线和机械臂朝向

地图右为+X、上为+Y，单位mm。原点声明时车中心在启停1原中心地图(2250,2250)，车头朝图左。固件局部X朝初始车头、Y朝初始车左；地图坐标为 `(2250−localX,2250−localY)`。转向过程中整个世界坐标系不变；`run forward/left`也仍是这个初始世界方向，不是旋转后的车头方向。

机械臂安装于车头右侧，即IMU −Y。原料站车头朝图左，粗加工站车头朝图右，左侧作业站车头朝图下，才能让车右侧靠近工位。源码航向0/180000/90000mdeg分别对应这些朝向。±180°等价；里程计可累计到−360°/−720°，不应因此重新origin。

中央路线固定站序：启停1 → 原料1 → 粗加工1 → 左侧作业1 → 原料2 → 粗加工2 → 左侧作业2 → 启停2 → 启停1。

| 粗加工1/2 | 1050,1975 | 1200,275 | 图右 |

启停区宽300mm与名义车宽相同，没有停车误差余量，所以本版最终两个蓝区目标明确向场内各内缩20mm。回起点目标与原中心相差约28mm，**这是计划偏置，不是定位误差**；量回程误差应对照(2230,2230)标记。若比赛要求整车完全压在300mm蓝区内，需要实测真实占用尺寸并按规则重新设计停车目标，不能据此声称满足正式比赛边界。

原地图左侧标注是“暂存区”，用户任务又涉及精加工；本版统一称左侧作业站，未凭空增加第二个位置。二维码停车和物料圆心精对准未加入本次快速跑图；后续比赛流程再按现场工位补充。

原料到粗加工经中央竖通道；粗加工到左站、左站回原料经中央交叉口圆滑过渡。最后两段经下侧/右侧外围返回。四块黄色障碍采用地图[550,1000]及[1400,1850]在X/Y方向的组合，每块450mm。

车身模型为300×300mm方形，采用定向矩形OBB与四块障碍SAT分离轴检测；不是只检查中心点。规划对障碍留15mm几何裕量，运行估计轮廓检查留5mm。400mm直通道里不能原地转45°（占宽约424mm）；旋转集中于通过轮廓检查的交叉口。路径采样检查不等于经过认证的连续扫掠体证明，更不是已校准的定位置信区间。

该地图是固定障碍地图，没有随机障碍感知、雷达避障或在线重规划。不能用它宣称完成2027赛题的随机障碍要求。

## 5. 连续执行和控制设计

`nav_route.c`把三次Hermite位置曲线、五次航向插值离散成静态路径；导引点保留非零速度，只有显式stop点速度为0。前后扫描用速度、名义加速度、曲率及四轮变化约束形成启发式速度包络；它不是TOPPRA最优求解器，也没有严格jerk最优/全局约束可行性证明。

名义路径加速度参数0.60m/s²（此前高速段0.10），曲率速度项0.60m/s²，参考轮变化约束参数200RPM/s；最终轮指令变化限制240RPM/s（此前30）。反馈、限幅及离散采样使实际机体加速度不等于这些参数。没有实测新的电流、打滑、jerk或载荷稳定性。

较长、航向不变的样条段采用200RPM预算，其余150RPM；参考留12%轮速反馈余量。离开蓝区的最初100mm有连续25RPM预算，不停车，以处理边界零余量和逐轮更新。不是全路线为了压误差降速。

跟踪器采用世界XY误差＋速度反馈＋加速度前馈，航向独立跟踪；统一逆运动学后按四轮最大值同比缩放，再统一限制轮变化，积分用实际分配结果回算。不能把平移200RPM和转向150RPM简单相加。纯旧 `goto/pose` 指令保留原慢速调试路径，仍单段停稳、最多100RPM；新加速连续方案的入口是 `route`，不是把旧pose参数硬改200。

航向参考进度根据跟踪滞后连续调节，同时缩放前馈，避免“参考时钟变慢但前馈仍全速”的不一致。导引点不发FE、不重启控制、不重绑里程计；作业站停稳后继续同一条路线。

运行的10°航向偏差阈值是高速轨迹的故障边界，**不是精度目标**；普通旧单段仍为3°。定向车身碰撞检查独立存在。到站要求估计位置误差<6mm、航向<0.5°、速度<8mm/s、角速度<0.025rad/s，连续3个周期，然后才记STATION。最终应用层再检查停稳位置/航向。所有这些都是估计量，实车另量。

## 6. 里程计与短时预测

累计位姿沿用nav1h：50ms公共时间网格，对四轮累计编码器和IMU航向插值后取位移，SE(2)积分。base是标准麦轮增量；fused是去转动项、按对角轮一致性降权的2×2位移最小二乘，不再把平滑后的速度积分成距离。两套均持续记录，本版缺省base。

已有使能的单段重启不重复F3、不丢历史；真实禁能转使能时仍验证ACK、静止及计数基线。200RPM合法编码器变化阈值已按速度上限、65536计数/转及余量换算；不是删除计数跳变保护。

建议沿用待复验的 `odom delay 55 0`、`odom lever 195`。这来自此前两圈的轮/IMU转动一致性辨识，包含滤波/采样/建模误差，不是已测纯通信延迟。镜像初始值仍0ms/220mm，必须明确发送配置；比例12924/13389输入脉冲每米保持不变。

本版新增控制影子预测：记录匹配成功的F6 ACK指令历史，用有界一阶响应推进最多250ms的轮速/位移；转动使用对齐IMU及短时陀螺数据，返回独立的控制位姿。它绝不写回base/fused，不伪造编码器样本，也不拿ACK当实际速度或到位。

有效响应时间初始160ms，通过实测轮速度变化与指令历史中点回归缓慢更新，限制60～350ms，只影响预测和前馈。`[RESPONSE] estimate_ms/accepted_samples`用于检查。它估计的是简化有效响应，不能等同质量、摩擦或打滑真值。指令与反馈不激励时不更新；异常/不足样本保持原值。这不是完整ADRC，也不能替代独立定位。

驱动轮共同打滑、尺度误差和IMU航向漂移仍无法只靠本套输入独立消除。纯里程计回到(0,0)不是地面回零证据。未来加被动编码轮、视觉/雷达位姿后才有独立的长期XY校正来源。

## 7. 下一次实车调试，按此顺序

先核对裸底盘、轮向、IMU安装、轮廓和场地，确认急停通路；记录本版尚未实测。下载后只读 `status/odom/perf/imu`，检查版本、时钟、无通信错误、四轮反馈连续、IMU angle/gyro新鲜、上电无自动动作。先做四方向100mm/5RPM与一次转向方向确认。机械臂未合并，本次不接舵机/升降测试。

车放平静止后可做 `imu tx on` → `imu cal acc`（约5秒）→ 等CALSW=0确认；必要时 `imu cal check` → `imu drift`（10秒）→ `imu tx off`。中途移动、超时或校准不确定均不算成功。`imu save`是显式写传感器参数，本次流程默认不发。

1. 车摆启停1原中心(2250,2250)，车头图左；蓝区两个内缩停车目标另作标记。整圈只发一次origin。
2. 设置 `clear`、`mode base`、`algorithm cascade`、`control xy`、`odom delay 55 0`、`odom lever 195`；等反馈恢复；`origin`后至少等1秒，确认valid=1/fault=0。
3. `limit 100`、`route plan 50`只生成路线，看到valid=1才可 `route start`。这是首次中央路线/方向/轮廓验收，最终速度方案不因这一轮永久降低。
4. 各站STATION应在相应工位停稳，导引点不整段停车；碰擦、压线、明显抖动/打滑、站点漂移或FAULT立即结束，不自动重试、不在途中origin“修正”。异常保存本地日志，不上传数据。
5. 回同一起点/同一朝向，`clear`，确认反馈与轮廓后 `limit 150`、`route plan 75`；通过再回起点 `limit 200`、`route plan 100`。这是当前请求的目标档，200是四轮实际指令上限，不是保证地面实速。
6. 分别看原料/粗加工/左站地面标记，而不只看终点。目标：不压黄线、无明显滑移/顿挫，到站朝向≤1°，各站误差暂以≤20mm为验收目标，整圈回程对内缩目标≤20mm；这些是待验收标准，不是既成成绩。场地/量具不足时明确写“目测”，不要报毫米级精度。
7. 统计从route start到DONE的整圈时间，同时区分参考轨迹时间、准备时间、停稳时间和故障停止。约65～71秒只是离线基准，实车超过1分钟时先查轮速饱和、模型响应、轨迹进度、通信与站点判稳，不按终点误差硬加补偿。
8. base验收后再同场同档 `mode fused`重跑，保持所有其他参数、起始标记和IMU处理一致；不要用两套估计自己输出的闭合误差排名。

每次换档需重新 `route plan`，同一圈中不能改模式/参数。`!`可直接发单字符；故障会FE＋失能所有轮，必须查原因、重新摆位后人工清除，不能自动续跑。

后续顺序：裸车目标档 → 带收拢固定的机械臂重复并重新评估动力响应 → 每站停住量真实夹点与工位偏差，记站点补偿 → 最后模拟比赛节拍。到时候再加入5秒扫码、每5秒夹一次、三工位大致摆放；颜色、圆心识别暂不作为该阶段前提。不能把不含等待的1分钟跑图当完整比赛用时。

## 8. 机械臂与最终合并

机械臂USART1 PA9/PA10调试；升降Emm5 UART4 PC10 TX/PC11 RX；夹爪/云台/料盘分别PC6/PC7/PC8。夹紧1560μs、松1850μs，云台车内1000/车外2130，料盘550/1450/2350，中间为默认工位。完整命令和重新标零步骤见 `arm/docs/serial_protocol.md`。

`grab [1|2|3]`车外入盘；`rough [1|2|3]`盘取料放粗加工；`stack [1|2|3]`盘取料叠放。grabpick、grabdrop、tray、rough、stack、clearance各自标定，tray不等于grabdrop。Flash保存高度不使掉电后Emm累计计数成为物理绝对高度。新板/掉电后要在可重复物理基准恢复，未知位置不能盲发动作。

上电PWM关闭，seed是立即输出当前已知姿态，不是缓慢寻找零点；SERVO_DONE只说明PWM到目标，无位置/接触传感器。单独执行器供电，共地，不能由主控3V3给所有舵机提供动力。此前硬件烧毁事件不能据程序ACK推断为软件或电源已安全。

合并前必须解决UART4冲突：底盘PA0/1和机械臂PC10/11是同一个外设，不能各初始化一个。建议把升降分配独立USART2 PA2/3，或先确认电气层后统一1～5地址事务仲裁；本次没有实施。IMU USART3 PD8/9与原视觉PB10/11也是同一个外设，视觉要另选独立外设。uart.docx协议本轮未合并。

统一main/时钟/ISR/watchdog/Flash布局；底盘停稳才夹取，机械臂避让姿态确认才开车。任务ACK、DONE、FAULT分开。底盘停机不能默认松爪。不要拼接两个main或两份UART驱动。

## 9. Flash和运算开支

底盘链接区384KiB，保留sector7：0x08060000～0x0807FFFF，机械臂保存配置也用这个区域。下载前备份目标芯片，核对F407/512KiB及正确探针，禁止整片擦除。当前底盘已大于64KiB，需要覆盖sector0～4；旧nav1h只擦0～3的脚本不再适用。使用HEX按镜像范围擦除/校验，保留其余扇区；这是下载操作说明，本轮没有执行。

新路线静态缓冲约49KiB，无堆分配；总RAM占用包含8KiB栈预留，详细数值见构建摘要。100ms控制、50ms里程计，硬浮点；保留控制计算10ms超时、反馈300ms等保护。规划耗时由ROUTE_PLAN_PERF输出，运行最大周期由perf输出；桌面测试DWT为0，不能当F407耗时。当前代码没有本版裸板DWT实测，更没有据此承诺全部实时开支。

建议上车先看无动作规划用时和perf/log_drops，再跑低档。若规划导致看门狗复位，不能当作串口坏；应优化/分片规划。运动中不使用断点halt来观察控制，以免冻结控制或触发独立看门狗。
