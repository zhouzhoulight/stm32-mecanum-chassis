# WT901CTTL：官方能力、当前接入与校准（2026-10-29）

此功能增量以v2.1.5为基础，加入双向寄存器查询、静止校准、漂移测量和软件参考归零；电机控制参数保持。原始实测日志由用户私下转发，不包含在此分支。校准命令的读回仅表明观察到工作状态，不能当作精度验收。

## 官方资料与型号边界

- [维特 WT901C 产品页](https://www.wit-motion.com/StandardPrecisionTilt/83.html)：三轴加速度、三轴角速度、三轴磁场及内置姿态解算。不要把俯仰/横滚精度宣传值当成车体航向精度保证。
- [厂家标准协议说明](https://wit-motion.gitbook.io/witmotion-sdk/wit-standard-protocol/wit-standard-communication-protocol)：CALSW为可读写寄存器，普通串口指令、输出内容和读回格式。
- [厂家官方 SDK](https://github.com/WITMOTION/WitStandardProtocol_JY901/tree/main/STM32F1/STM32Core_SDK_Normal/Source/wit_c_sdk)：协议字段依据 `REG.h`；时序依据 `WitStartAccCali` / `WitStopAccCali` / `WitStartMagCali` 等实现。

官方通用 SDK 还定义四元数、输出内容/频率、滤波带宽、六轴/九轴选择、安装方向、零偏参数和保存命令。通用 SDK 的全部寄存器并不保证每一版 WT901CTTL 都支持；GPS、气压高度等通用字段也不代表本型号内置这些硬件。先读实际固件和配置，再增加写入入口。

| 功能 | 对本车的用途与边界 |
|---|---|
| 加速度/陀螺仪静止校准 | 传感器物理放平、整车静止时修正传感器偏置。不能让有倾斜的安装靠校准强行变成水平 |
| 磁场校准 | 九轴融合的环境标定，须按该型号说明绕三轴转动；不能等同于底盘平面转一圈，更不能消除电机电流变化造成的全部动态磁干扰 |
| 六轴模式 | 不使用磁场约束航向，避开磁扰，但航向会积分漂移 |
| 九轴模式 | 融合磁场约束长期航向；车架、电机、磁性物料和电流可能影响，必须做本车对照 |
| 航向参考归零 | 本项目使用 STM32 软件参考，原始 yaw 不变，不写传感器，不会消除漂移 |
| 输出频率/滤波带宽 | 与控制更新率和延迟有关，是两个参数；不盲目调最大、不同时改多个参数 |
| 静止自动校准 | 厂家不同固件的寄存器定义可能不同；当前 SDK 0x63 名为 GYROCALTIME，不能照网帖把它直接当开关写入 |

硬件六轴/九轴切换、硬件 Z 归零、磁场校准暂不开放写入命令。先用 `imu read mode` 取得实物返回值。航向保持原有逻辑仍取相对 yaw，`imu zero` 只帮助观察，不替换原控制器的动作起点参考。

## 接线

保留当前底盘接线：控制台 USART1 PA9/PA10，电机 UART4 PA0/PA1，IMU USART3 PD8/PD9；115200 8N1。WT901 TX→PD9；**新增 PD8→WT901 RX**；GND共地。PD8是TTL信号，不能接电源，也不能接RS232/RS485接口。供电沿用已核实的模块电源。

上电默认 RX_ONLY，PD8输入高阻，不自动写传感器。`imu tx on` 仅启用串口TX脚，本身不发送字节。重启后需要重新启用。

## 新命令

| 命令 | 行为 |
|---|---|
| `imu` | 原始角度/三轴角速度、帧新鲜度、错误计数、服务状态及软件相对yaw；辅助加速度/磁场帧计数 |
| `imu zero` | 将当前yaw记为软件参考，不改传感器角度，不保存到Flash |
| `imu drift` | 10秒静止测量，输出yaw变化、按本次时长外推的每分钟变化、gyroZ平均值及峰峰值；统计每次主循环观察到的新样本，不是全速原始采样 |
| `imu cancel` | 取消读配置或静止测量；校准可能运行时改用 `imu cal stop` |
| `imu tx on` / `imu tx off` | 启用发送 / 恢复PD8高阻；校准期间不允许直接关闭TX |
| `imu read mode` | 读取0x24起四个寄存器；官方定义首值0=九轴，1=六轴 |
| `imu read output` | 读取0x02起：输出内容、输出率编码、波特率编码、AX偏置 |
| `imu read filter` | 读取0x1F起：带宽编码、陀螺仪量程、加速度量程、休眠 |
| `imu read version` | 读取0x2E起，首值为版本原始值，不擅自解释成特定版本号格式 |
| `imu cal acc` | 解锁→启动静止加速度/陀螺仪校准→5秒后请求正常模式→等待100毫秒→读回CALSW；**不自动保存** |
| `imu cal check` | 只读检查CALSW，可在退出状态不明时使用 |
| `imu cal stop` | 请求退出校准并检查CALSW=0；用于提前停止或超时后的恢复 |
| `imu save` | 显式请求传感器保存当前参数；普通协议无保存ACK，断电保留情况需另外验证 |
| `imu baud N` | 原有MCU接收速率配置，不修改传感器速率；会回到RX_ONLY并清除本次软件参考 |

本程序沿用原解码的 ±2000°/s 换算；如果实读量程不一致，应先核对型号协议再修正换算，不能用错误单位做漂移结论。加速度和磁场保留原始计数，不伪造未知量程单位。

校准发起前软件要求角度/角速度均新鲜、roll/pitch在±5°内且三轴角速度绝对值不大于3°/s；这只是明显错误拦截，不能替代水平仪或人工静置。过程中检测明显运动会请求提前退出。校准、读配置、测漂移期间拒绝新的电机运动命令；`stop` 始终保留。程序不上电自动校准，不改电机PID、电流、模式或每米脉冲系数。

### 建议实际操作

1. 电机停止，车架和传感器真实放平，静置至读数稳定。`imu`确认帧正确。
2. `imu drift`，等待10秒结果，记录校准前数据。
3. `imu tx on`，逐条发送 `imu read version`、`imu read mode`、`imu read output`、`imu read filter`，每次等返回后再发下一条。
4. `imu cal acc`，全过程保持水平、静止，约5秒后等 `CALSW=0 observed`。这只表明观察到正常模式，不代表精度已经改善。
5. 再执行 `imu drift` 做同条件比较，必要时观察更久；结果稳定且配置确认正确后再 `imu save`。
6. `imu zero` 设置观察参考，然后进行经现场确认的短程无纠偏/有纠偏对比。

如果0x5F超时，先检查新增TX线及固件是否支持，不能反复盲写。校准退出状态不明时会锁住运动，用 `imu cal stop` 恢复；仍无响应可先用 `imu cal check` 或 `imu read version` 只读检查，再检查接线/使用官方工具确认状态。不能以保存指令已发出认定Flash已保存。

普通串口的0x5F回复不包含请求的基址。本项目一次只允许一个读请求，超时不自动重试，超时/取消后至少等1秒再发新读请求。迟到或重复回复的地址歧义是协议限制，返回值仅作诊断，不能用于自动改变六轴/九轴或设置。

## D02如何解释

仓库D02是 `left_diag_160`，源码强制 correction=0，实测15条有效yaw的终值变化−0.016°；这只是一小段的无纠偏诊断，不能用它判定航向纠偏有效或无效。四台残余轴误差约0.32～0.61°，均超过0.3°到位窗口，是原分段流程停住的重要线索。

真正的纠偏入口是 `left_hold_1600/16000`。用户补充的后续实测尚未提交，不能凭本地旧记录替代它。静止校准改善的是传感器测量；分段衔接、补偿方向/增益、串口时序和轮胎打滑须分别验证。首次对照沿用相同5RPM、1600脉冲，记录偏航曲线、驱动器状态及实际位移，不能只比较一条最终yaw。
